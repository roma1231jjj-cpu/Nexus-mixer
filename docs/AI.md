# ИИ-конверсия голоса

Nexus-Mixer умеет три вещи с голосом:

1. **DSP-обработка** — питч, форманты, тембр, денойз. Работает на CPU, почти без
   задержки, не требует моделей.
2. **RVC-конверсия** — замена тембра голоса локальной нейросетью (Retrieval-based
   Voice Conversion). Требует GPU для комфортной задержки.
3. **HYBRID** — DSP-подготовка → RVC → пост-обработка.

Всё выполняется **локально**: аудио не уходит в сеть.

---

## 1. Режимы

| Режим | Что происходит | Задержка | CPU/GPU |
| --- | --- | --- | --- |
| `OFF` | Байпас, только гейн и маршрутизация | 0 | — |
| `DSP` | Питч/формант/тембр/денойз без нейросети | 5–20 мс | CPU |
| `AI` | RVC-модель заменяет тембр | 80–350 мс | GPU (CPU — медленно) |
| `HYBRID` | Денойз → RVC → EQ/компрессор/сатуратор | 90–380 мс | GPU + CPU |

Переключение на лету сопровождается кроссфейдом 20–40 мс, чтобы не было щелчка.

---

## 2. DSP-цепочка

```
вход → denoise → highpass 80 Гц → pitch shift → formant shift
     → tilt EQ → компрессор → сатуратор → dry/wet → выход
```

- **Denoise** — RNNoise (48 кГц, кадр 10 мс) или спектральное вычитание.
  Включается флагом `denoise`.
- **Pitch** — phase vocoder / WSOLA. Диапазон −24…+24 полутона.
- **Formant** — независимый сдвиг формант −12…+12. Реализуется ресемплингом
  спектральной огибающей, а не простым питчем.
- **Tilt** — наклон АЧХ голоса, −20…+20 дБ (поле `voiceTiltDb`).
- **Dry/wet** — `mix`, 0…100 %.

DSP-режим — это ещё и страховка: если GPU занят или модель не загрузилась,
пользователь всё равно получает обработанный голос.

## 3. RVC-пайплайн

```
PCM 48k
  │
  ├─► resample 16k ─► HuBERT / ContentVec ─► content features
  │
  ├─► f0 extraction (RMVPE / CREPE) ──────► pitch contour
  │
  ├─► feature retrieval (FAISS index) ────► blended features
  │
  └─► generator (ONNX, HiFi-GAN/VITS) ───► PCM 40k/48k
                                              │
                              resample 48k ───┘
                                              │
                                   crossfade + dry/wet
```

Компоненты:

| Компонент | Назначение | Формат |
| --- | --- | --- |
| Content encoder | HuBERT/ContentVec, лингвистический контент | `.onnx` |
| F0 extractor | RMVPE (точнее) или CREPE | `.onnx` |
| Index | FAISS-индекс тембра для retrieval | `.index` |
| Generator | Синтез вейвформы | `.onnx` |

### 3.1 Модель

```
models/
  my-voice/
    manifest.json
    generator.onnx
    hubert.onnx
    rmvpe.onnx
    my-voice.index
```

`manifest.json`:

```json
{
  "id": "my-voice",
  "name": "My Voice",
  "author": "user",
  "language": "ru",
  "version": "v2",
  "sampleRate": 48000,
  "f0": true,
  "sizeMb": 220,
  "sha256": "…",
  "files": {
    "generator": "generator.onnx",
    "content": "hubert.onnx",
    "f0": "rmvpe.onnx",
    "index": "my-voice.index"
  }
}
```

При импорте проверяются: наличие файлов, версия, sample rate, совпадение SHA-256.
Модели без индекса работают, но тембр менее точный.

### 3.2 Параметры UI → пайплайн

| Параметр | Диапазон | Влияние |
| --- | --- | --- |
| `pitch` | −24…+24 | Транспонирование f0 |
| `formant` | −12…+12 | Сдвиг формант (пол не меняется) |
| `indexRate` | 0…1 | Баланс «генератор ↔ retrieval» |
| `chunkMs` | 40…320 | Меньше — ниже задержка, больше артефактов |
| `extraContext` | кадры | Контекст по краям чанка |
| `crossfadeMs` | 0…100 | Склейка соседних чанков |
| `gpuIndex` | −1 = CPU | Выбор GPU |
| `denoise` | bool | Предобработка |
| `mix` | 0…100 % | Сухой/обработанный |
| `gateDb` | −90…0 | Байпас при тишине |

## 4. Чанки и задержка

RVC не умеет потоково обрабатывать бесконечный сигнал, поэтому аудио режется на
чанки с перекрытием.

```
|---- chunk N-1 ----|
          |---- chunk N ----|
                    |---- chunk N+1 ----|
          |xfade|
```

Бюджет задержки:

```
latency ≈ chunk_ms + crossfade_ms/2 + inference_ms + буферы
```

| chunk | Ожидаемая задержка (GPU, RTF 0.25) | Качество стыков |
| --- | --- | --- |
| 40 мс | ~60–90 мс | много артефактов |
| 80 мс | ~100–140 мс | приемлемо |
| 120 мс | ~150–190 мс | хорошо |
| 160 мс | ~190–240 мс | рекомендуется |
| 240 мс | ~280–330 мс | студийно |
| 320 мс | ~360–420 мс | для записи, не для live |

Задержка важна для live-стрима; для записи и подкастов лучше качество.

## 5. Sidecar

Тяжёлый ML не встраивается в Rust-движок: инференс живёт в отдельном процессе,
чтобы падение или перезагрузка модели не роняла аудиопоток.

```
┌─────────────────┐   PCM + команды    ┌──────────────────────┐
│  Rust engine    │◄──────────────────►│  Python sidecar      │
│  ring buffer    │  localhost / pipe  │  onnxruntime-gpu     │
└─────────────────┘                    │  numpy, faiss        │
                                       └──────────────────────┘
```

### 5.1 Протокол

Рекомендуемый вариант — **локальный TCP/ZeroMQ с length-prefixed кадрами**:

```
[ u32 length ][ JSON header ][ f32 PCM payload ]
```

Команды:

| Команда | Поля | Ответ |
| --- | --- | --- |
| `hello` | версия протокола | `ready`, список моделей |
| `load` | `modelId` | `loaded` / `error` |
| `unload` | — | `ok` |
| `process` | `seq`, `sampleRate`, `channels` | `[seq, PCM]` |
| `status` | — | RTF, latency, GPU, память |
| `shutdown` | — | `bye` |

Правила:

- sidecar никогда не блокирует аудиопоток: при отсутствии ответа движок играет
  dry-сигнал;
- каждому кадру присваивается `seq`, опоздавшие кадры отбрасываются;
- backpressure: если очередь > 3 чанков, включается bypass;
- перезапуск sidecar — автоматический, с экспоненциальной задержкой.

Для минимальной задержки позже можно перейти на **shared memory + named events**:
движок пишет PCM в кольцо, sidecar читает и пишет результат в обратное кольцо.

### 5.2 Запуск

```powershell
python -m nexus_ai.sidecar --model-dir "%APPDATA%\Nexus-Mixer\models" --port 47831
```

Rust запускает процесс при включении AI-режима и останавливает при выключении.
Логи sidecar пишутся в `%LOCALAPPDATA%\Nexus-Mixer\logs\ai.log`.

## 6. Производительность

| Железо | RVC v2, 48 кГц, chunk 160 | Ожидаемый RTF |
| --- | --- | --- |
| RTX 4090 | fp16 | 4–6 |
| RTX 3060 12 ГБ | fp16 | 1.5–2.5 |
| GTX 1650 4 ГБ | fp16 | 0.8–1.2 |
| Intel i7 (8 ядер) | ONNX int8 | 0.3–0.6 |
| Ryzen 5 (6 ядер) | ONNX int8 | 0.25–0.5 |

Условие комфортного live-режима: **RTF ≥ 1.2**. Если RTF ниже, UI предлагает
DSP-режим или больший chunk.

Оптимизации:

- ONNX Runtime с CUDA / DirectML / OpenVINO EP;
- fp16 на GPU, int8-квантование для CPU;
- кэш content-энкодера между чанками;
- отключение retrieval при `indexRate = 0`;
- предзагрузка модели в VRAM при старте.

## 7. Качество

Что влияет на результат:

- **Модель** — доминирующий фактор. 10–20 минут чистой речи, один язык, без
  музыки и эха.
- **`indexRate`** — 0.5–0.75 обычно лучше, чем 1.0 (меньше «металла»).
- **`formant`** — компенсирует разницу мужской/женский голос.
- **`denoise`** — обязателен для дешёвых микрофонов, но может «съесть» воздух.
- **`crossfadeMs`** — 20–40 мс убирает стыки, больше — размывает атаки.

Метрики, которые снимаем:

- RTF и p95 задержки;
- число underrun/overrun;
- спектральная дистанция до целевого голоса;
- субъективный MOS на эталонном наборе;
- f0-ошибка на устойчивых гласных.

---

## 8. Приватность и безопасность

- Никаких сетевых вызовов: sidecar слушает только `127.0.0.1`.
- Модели — файлы на диске, без исполняемого кода.
- Импорт модели проверяет SHA-256 и структуру каталога.
- Не бандлим чужие голоса: лицензия модели — ответственность пользователя.
- В логах нет сырого аудио, только метаданные и метрики.

## 10. Критерий готовности

- RTF ≥ 1.5 на RTX 3060 при chunk 160 мс.
- End-to-end задержка < 240 мс.
- Нет щелчков на стыках при `crossfade ≥ 20 мс`.
- Переключение AI ↔ DSP без разрыва звука.
- Падение sidecar не останавливает микшер.
- Аудио не покидает машину.
